O que é Linux

Linux é o nome do kernel (núcleo) desenvolvido por Linus Torvalds. Uma distribuição Linux reúne: Kernel + bibliotecas + ferramentas + aplicativos + gerenciador de pacotes + interface gráfica.

O kernel é o núcleo do sistema operacional, responsável por intermediar a comunicação entre programas e hardware.

Linux ≠ Ubuntu — Ubuntu é uma distribuição, não o sistema em si.

Destaque

Kernel Linux

Conceito

Kernel Linux

O kernel é a parte central do sistema operacional. Administra recursos fundamentais:

- Processador (CPU)
- Memória (RAM)
- Processos
- Dispositivos (drivers)
- Armazenamento
- Rede
- Sistema de arquivos
- Chamadas de sistema (system calls)

O usuário não interage diretamente com o kernel — a comunicação ocorre via programas, bibliotecas e Shell.

Conceito

/home, /etc, /var em Detalhe

/home — contém os diretórios pessoais dos usuários comuns. Exemplo: /home/joao. O símbolo ~ representa o diretório pessoal do usuário atual.

/etc — contém arquivos de configuração do sistema. Arquivos importantes:
- /etc/passwd — informações de usuários
- /etc/shadow — credenciais protegidas
- /etc/group — grupos
- /etc/hosts — resolução local de nomes
- /etc/fstab — sistemas de arquivos montados na inicialização

/var — armazena dados que mudam durante a execução:
- /var/log — logs do sistema e aplicações
- /var/cache — caches
- /var/spool — filas de impressão e e-mail

Permissões — r, w, x

Conceito

Permissões — r, w, x

O Linux trabalha com três permissões básicas:

- r = read (leitura) → 4
- w = write (escrita) → 2
- x = execute (execução) → 1

Valores octais:

PermissãoValorSignificado
rwx7Leitura, escrita e execução
rw-6Leitura e escrita
r-x5Leitura e execução
r--4Apenas leitura
---0Sem permissões

Grupos de permissões:

rwx r-x r--

- Proprietário → rwx (7)
- Grupo → r-x (5)
- Outros → r-- (4)

Octal: 754

chmod — Modificar Permissões

Conceito

chmod — Modificar Permissões

chmod = Change Mode

Altera permissões de arquivos e diretórios.

Sintaxe octal:

chmod 755 arquivo


Significa:
- Proprietário → 7 → rwx
- Grupo → 5 → r-x
- Outros → 5 → r-x

Sintaxe simbólica:

chmod u+x arquivo    # adiciona execução para o proprietário
chmod g-w arquivo    # remove escrita do grupo
chmod o=r arquivo    # define leitura para outros

⚠️ chmod 777 = rwxrwxrwx — não é seguro dar permissão total a todos.

Destaque

Conceito

chown — Alterar Proprietário

chown = Change Owner

Altera o proprietário de um arquivo ou diretório.

chown usuario arquivo
chown usuario:grupo arquivo   # altera proprietário e grupo
chown -R usuario:grupo pasta/ # recursivo

chgrp — altera apenas o grupo.

🧠 Bizu:
- chmod → permissões
- chown → proprietário
- chgrp → grupo

Usuários — UID, GID e Root

Conceito

Usuários — UID, GID e Root

O Linux possui um sistema de usuários e grupos.

- UID (User ID) — identificador numérico do usuário
- GID (Group ID) — identificador numérico do grupo

root — superusuário tradicional do Linux.
- UID 0
- Possui privilégios extremamente elevados
- Não é apenas \"um administrador comum\"

Arquivos importantes:
- /etc/passwd — informações básicas das contas
- /etc/shadow — credenciais protegidas (senhas)
- /etc/group — informações sobre grupos
- /etc/sudoers — regras de autorização do sudo

⚠️ Não confunda /etc/passwd com /etc/shadow — o shadow armazena informações sensíveis de autenticação.

Conceito

sudo — Executar com Privilégios

sudo permite que um usuário autorizado execute comandos com privilégios elevados.

sudo comando

O usuário não precisa permanecer em uma sessão permanente de root.

Principais diferenças:

ComandoEfeito
sudo comandoExecuta o comando com privilégios de root (temporário)
sudo -iInicia uma sessão interativa como root
sudo -u usuarioExecuta como outro usuário

🧠 Bizu: sudo = executar com privilégios autorizados (não é uma conta, é um mecanismo).

Destaque

root ≠ sudo

Pegadinha

root ≠ sudo

Root é uma conta de usuário com UID 0, com privilégios ilimitados.

sudo é um mecanismo que permite usuários autorizados executarem comandos com privilégios elevados.

Não são a mesma coisa. O usuário pode usar sudo sem ser root.

O que é um Processo

Um processo é uma instância de um programa em execução.

Cada processo possui um identificador único:

PID — Process ID

Exemplo: um navegador aberto, um terminal, um servidor web — cada um tem seu próprio PID.

Destaque

PID e PPID

Conceito

PID e PPID

PID — Process ID (identificador do processo).

PPID — Parent Process ID (identificador do processo pai).

Processos formam uma estrutura hierárquica: o processo pai cria processos filhos.

🧠 Bizu:
- PID = quem sou
- PPID = quem me criou

Exemplo: o Shell (bash) é o pai dos comandos executados a partir dele.

kill — Sinais para Processos

Conceito

kill — Sinais para Processos

O comando kill envia sinais para processos — não significa necessariamente \"matar\".

Sinais importantes:

SinalNúmeroEfeito
SIGTERM15Solicita encerramento gracioso (padrão)
SIGKILL9Força encerramento imediato (não pode ser bloqueado)
SIGSTOP19Pausa o processo
SIGCONT18Continua o processo pausado
SIGHUP1Recarregar configuração
 
kill 1234         # SIGTERM para o processo 1234
kill -9 1234      # SIGKILL (força encerramento)
kill -HUP 1234    # SIGHUP (recarrega configuração)

🔴 Pegadinha: SIGKILL (9) não pode ser capturado, bloqueado ou ignorado pelo processo.

Conceito

Daemons e Processos em Plano de Fundo

Daemon — processo que funciona em segundo plano para prestar um serviço.

Exemplos: servidor SSH, servidor web (Apache/Nginx), serviço de impressão, serviço de rede.

Processos em primeiro plano (foreground):
- O terminal fica associado à execução
- O usuário aguarda o término

Processos em segundo plano (background):
- O Shell continua recebendo comandos
- O operador & inicia o comando em segundo plano

comando &   # executa em segundo plano

tar, gzip e Compactação

Conceito

tar, gzip e Compactação

tar — empacotamento (arquiva vários arquivos em um só).

gzip — compressão (reduz o tamanho do arquivo).

.tar.gz = empacotamento + compressão.

tar -czf arquivo.tar.gz pasta/   # empacota e comprime
tar -xzf arquivo.tar.gz          # desempacota e descomprime
tar -cf arquivo.tar pasta/       # apenas empacota
tar -xf arquivo.tar              # apenas desempacota

Opções:
- c — create (criar)
- x — extract (extrair)
- z — gzip (compactar/descompactar)
- f — file (nome do arquivo)
- v — verbose (mostrar progresso)

⚠️ Pegadinha: tar e gzip não são a mesma coisa.
- tar = empacotamento
- gzip = compressão

Comandos Básicos do Linux

pwd — Onde estou?

pwd = Print Working Directory

Exibe o diretório de trabalho atual.

Exemplo:

```bash

pwd

/home/usuario

```

🧠 Bizu: pwd responde "Onde estou?"

cd — Navegar entre Diretórios

cd = Change Directory

| Comando | Função |

|---------|--------|

| cd /home | Vai para /home |

| cd .. | Volta ao diretório anterior (subir um nível) |

| cd ~ | Vai para o diretório pessoal do usuário |

| cd - | Volta ao diretório anterior utilizado pelo Shell |

Exemplo:

```bash

cd /etc

cd ~

```

cp, mv e rm — Copiar, Mover e Remover

cp — Copia arquivos

```bash

cp arquivo.txt backup.txt

cp -r pasta/ destino/ # copia recursivamente (com subdiretórios)

```

mv — Move ou renomeia

```bash

mv antigo.txt novo.txt # renomeia

mv arquivo.txt /home/ # move para outro diretório

```

rm — Remove arquivos

```bash

rm arquivo.txt

rm -r pasta/ # remove recursivamente (CUIDADO!)

rm -f arquivo.txt # força remoção sem confirmação

```

🔴 Atenção: rm remove diretamente, sem enviar para a Lixeira. Cuidado com rm -r e comandos como root.

Permissões e Usuários no Linux

Diagrama de permissões Linux

chmod — Modificar Permissões

chmod = Change Mode

Altera permissões de arquivos e diretórios.

Sintaxe octal:

```bash

chmod 755 arquivo

```

Significa:

  • Proprietário → 7 → rwx
  • Grupo → 5 → r-x
  • Outros → 5 → r-x

Sintaxe simbólica:

```bash

chmod u+x arquivo # adiciona execução para o proprietário

chmod g-w arquivo # remove escrita do grupo

chmod o=r arquivo # define leitura para outros

```

⚠️ chmod 777 = rwxrwxrwx — não é seguro dar permissão total a todos.

chown — Alterar Proprietário

chown = Change Owner

Altera o proprietário de um arquivo ou diretório.

```bash

chown usuario arquivo

chown usuario:grupo arquivo # altera proprietário e grupo

chown -R usuario:grupo pasta/ # recursivo

```

chgrp — altera apenas o grupo.

🧠 Bizu:

  • chmod → permissões
  • chown → proprietário
  • chgrp → grupo

sudo — Executar com Privilégios

sudo permite que um usuário autorizado execute comandos com privilégios elevados.

```bash

sudo comando

```

O usuário não precisa permanecer em uma sessão permanente de root.

Principais diferenças:

| Comando | Efeito |

|---------|--------|

| sudo comando | Executa o comando com privilégios de root (temporário) |

| sudo -i | Inicia uma sessão interativa como root |

| sudo -u usuario | Executa como outro usuário |

🧠 Bizu: sudo = executar com privilégios autorizados (não é uma conta, é um mecanismo).

Processos e Gerenciamento

kill — Sinais para Processos

O comando kill envia sinais para processos — não significa necessariamente "matar".

Sinais importantes:

| Sinal | Número | Efeito |

|-------|-------:|--------|

| SIGTERM | 15 | Solicita encerramento gracioso (padrão) |

| SIGKILL | 9 | Força encerramento imediato (não pode ser bloqueado) |

| SIGSTOP | 19 | Pausa o processo |

| SIGCONT | 18 | Continua o processo pausado |

| SIGHUP | 1 | Recarregar configuração |

```bash

kill 1234 # SIGTERM para o processo 1234

kill -9 1234 # SIGKILL (força encerramento)

kill -HUP 1234 # SIGHUP (recarrega configuração)

```

🔴 Pegadinha: SIGKILL (9) não pode ser capturado, bloqueado ou ignorado pelo processo.

Daemons e Processos em Plano de Fundo

Daemon — processo que funciona em segundo plano para prestar um serviço.

Exemplos: servidor SSH, servidor web (Apache/Nginx), serviço de impressão, serviço de rede.

Processos em primeiro plano (foreground):

  • O terminal fica associado à execução
  • O usuário aguarda o término

Processos em segundo plano (background):

  • O Shell continua recebendo comandos
  • O operador & inicia o comando em segundo plano

```bash

comando & # executa em segundo plano

```

Systemd e Gerenciamento de Pacotes

journalctl — Logs do Systemd

journalctl é utilizado para consultar registros mantidos pelo systemd-journald.

```bash

journalctl # todos os logs

journalctl -u serviço # logs de um serviço específico

journalctl -f # segue os logs em tempo real (tail -f)

jounalctl --since "2024-01-01"

journalctl -p err # apenas mensagens de erro

```

🧠 Bizu:

  • systemctl → serviços
  • journalctl → logs

Gerenciamento de Pacotes

Linux utiliza sistemas de gerenciamento de pacotes para instalar, remover, atualizar e resolver dependências.

Principais sistemas:

| Distribuição | Gerenciador | Comando de Instalação |

|--------------|-------------|----------------------|

| Debian, Ubuntu, Mint | APT | apt install pacote |

| Fedora, RHEL | DNF | dnf install pacote |

| Arch Linux | Pacman | pacman -S pacote |

| openSUSE | Zypper | zypper install pacote |

Comandos APT (Debian/Ubuntu):

```bash

apt update # atualiza lista de repositórios

apt install # instala pacote

apt remove # remove pacote

apt upgrade # atualiza todos os pacotes

apt search # busca pacotes

```

🧠 Bizu:

  • Debian/Ubuntu → APT
  • Fedora/RHEL → DNF
  • Arch → Pacman

Repositórios e Gerenciadores de Pacotes

Ferramentas Avançadas e Redes

Pipes — Conectando Comandos

O símbolo | (pipe) conecta a saída de um comando à entrada de outro.

Comando A → saída → Comando B

```bash

ls -la | grep .txt # lista arquivos e filtra por .txt

ps aux | grep firefox # lista processos e filtra por firefox

cat arquivo.txt | less # exibe conteúdo paginado

```

🧠 Bizu: Pipe = "pegue a saída daqui e mande para lá".

Redirecionamento de Entrada e Saída

O Shell permite redirecionar entradas e saídas.

| Operador | Função |

|----------|--------|

| > | Redireciona saída para um arquivo (sobrescreve) |

| >> | Redireciona saída para um arquivo (acrescenta) |

| < | Utiliza um arquivo como entrada |

| 2> | Redireciona saída de erro padrão |

| 2>&1 | Redireciona erro para a saída padrão |

| &> | Redireciona saída e erro para o mesmo arquivo |

```bash

echo "texto" > arquivo.txt # sobrescreve

echo "mais texto" >> arquivo.txt # acrescenta

grep "erro" < arquivo.txt # usa arquivo como entrada

comando 2> erros.txt # redireciona erros

```

⚠️ Pegadinha: > sobrescreve; >> acrescenta — não confunda!

grep — Pesquisar Padrões de Texto

grep (Global Regular Expression Print) pesquisa padrões em textos.

```bash

grep palavra arquivo.txt

grep -i palavra arquivo.txt # ignora maiúsculas/minúsculas

grep -r palavra pasta/ # pesquisa recursivamente

grep -v palavra arquivo.txt # mostra linhas que NÃO contêm

grep -n palavra arquivo.txt # mostra número das linhas

```

🧠 Bizu: grep = procurar texto dentro de arquivos.

find — Localizar Arquivos

find localiza arquivos e diretórios por critérios.

```bash

find / -name "arquivo.txt" # por nome

find /home -type f -size +10M # arquivos > 10MB

find /etc -type d -name "*.d" # diretórios terminados em .d

find . -perm 644 # por permissões

find . -mtime -7 # modificados nos últimos 7 dias

find . -exec comando {} \; # executa comando para cada arquivo

```

⚠️ Pegadinha:

  • grep pesquisa conteúdo (texto dentro dos arquivos)
  • find pesquisa arquivos e diretórios (nomes, metadados)

tar, gzip e Compactação

tar — empacotamento (arquiva vários arquivos em um só).

gzip — compressão (reduz o tamanho do arquivo).

.tar.gz = empacotamento + compressão.

```bash

tar -czf arquivo.tar.gz pasta/ # empacota e comprime

tar -xzf arquivo.tar.gz # desempacota e descomprime

tar -cf arquivo.tar pasta/ # apenas empacota

tar -xf arquivo.tar # apenas desempacota

```

Opções:

  • c — create (criar)
  • x — extract (extrair)
  • z — gzip (compactar/descompactar)
  • f — file (nome do arquivo)
  • v — verbose (mostrar progresso)

⚠️ Pegadinha: tar e gzip não são a mesma coisa.

  • tar = empacotamento
  • gzip = compressão

SSH — Acesso Remoto Seguro

SSH (Secure Shell) — utilizado para acesso remoto seguro a sistemas.

```bash

ssh usuario@servidor

ssh -p 2222 usuario@servidor # porta personalizada

ssh -i chave.pem usuario@servidor # autenticação por chave

```

Chaves SSH:

  • Chave pública — pode ser compartilhada (colocada no servidor)
  • Chave privada — deve permanecer protegida (nunca compartilhar)

🔴 Atenção: Nunca compartilhe sua chave privada.
